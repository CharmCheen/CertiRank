## 4. 口径与注意事项

1. **逻辑调用口径**：表内比较（含复核 / 修复路径的新比较）从响应表读取、按计费规则
   记账，不产生新物理调用；表外比较才需实际调用（两周计划 §3.3）。
2. **不含重试**：实测 420 次调用传输尝试均为 1 次、重试 0 次；物理重试上限按
   run manifest 另行约定并单独记账（两周计划 §7）。
3. **N=16 假设**：每次比较仍为 2 篇文档，单次调用 token 分布与 N=8 近似。
4. **先导配置**：12 次重复 / 对为两周计划 §3.3 的先导配置，不支撑低违约率统计认证。
5. **串行时间参考**：中位 0.78 秒 / 调用 → 核心合计 6,048 次约 1.3 小时；
   p95 5.0 秒 / 调用的情景约 8.4 小时。
   按计划 §3.3 以随机 / 交错顺序采集，分散时间漂移与服务版本变化。

## 5. 缓存与 token 敏感性

- 高档历史均值、无缓存：核心采集约 $1.66。
- 历史最大输入、输出128、最多3次尝试的假设：核心采集约 $9.02。

以上均按历史计价估算。高档输入采用历史查询均值，缓存和输出长度也可能变化；这些值无法构成新运行的金额上限。
第二个情景中的输入、输出和重试限制只是显式假设，尚未在真实适配器中实施。
付费运行仍需冻结实际 workload、当期计价、输入/输出限额、重试与累计金额上限、截止时间及授权；P6 live smoke 另列预算。
延迟情景没有尾部保证；历史已有约 5.6 小时的悬置请求。
