配套文档：[两周执行计划](CertiRank_两周执行计划_2026-10-15至2026-10-28.md)

> 核心判断：值得继续探索。首阶段围绕单一算子的复核预算分配与增量重算，验证执行结构是否提供超越置信度的有效信息。CertiRank 暂作项目代号，名称不代表已经获得严格认证能力。

## 1. 一句话定义与研究目标

研究语义 Top-K 中局部随机判断如何通过自适应比较路径改变最终结果，并利用执行轨迹选择值得复核的比较、复用未受影响的计算，在有限额外成本下提高独立执行的一致性，同时保持任务质量。

首阶段的问题表述：

> 给定固定数据、查询、模型接口、Prompt、输入顺序和物理算子，系统能否仅利用执行时可获得的信息，在相同额外预算下，比置信度复核或简单拓扑策略更有效地减少 Top-K 结果分歧？比较更新以后，增量执行能节省多少真实工作？

研究对象为语义查询引擎的物理执行层；模型作为外部比较服务。主要产出是执行机制、成本分析和实验依据。

## 2. 动机：为什么这个问题值得研究

语义 Top-K 可以通过 LLM 成对比较与 Quickselect、Heap、Tournament 等算法实现。一次局部判断既影响候选晋级，又可能改变后续比较对象。相同的不确定性水平，在不同执行位置可能对应不同的最终影响。

由此出现三个需要联合考虑的量：

1. **判断变化的可能性**：该比较再次调用时有多容易改变？
2. **结果影响**：比较变化会不会改变入选集合，影响几条记录？
3. **恢复成本**：调整判断后，需要新增多少比较，产生多少串行轮次？

模型置信度主要描述第一类信息；执行引擎额外掌握候选关系、控制流依赖、已经得到的比较结果以及可复用状态。课题的机会在于将这些信息转化为可验证的预算分配收益。

预期的系统价值包括：降低不必要的重复调用、减少局部更新后的重算、呈现成本与可靠性的取舍。若收益只存在于完整比较表事后分析中，在线系统无法获得这些信息，则不能据此宣称方法可用。

## 4. 研究范围与目标语义

### 4.1 首阶段固定范围

| 维度 | 首阶段选择 | 理由 |
| --- | --- | --- |
| 输出 | 无序 Top-K 集合；默认 K=3 | 聚焦成员资格变化，避免混入内部名次扰动 |
| 主算子 | 固定叶序与提取规则的 Tournament | 依赖关系明确，便于验证增量执行 |
| 对照算子 | 当前仓库已实现的 Top-K 算子 | 复用基础；先做对照，不要求完整优化器 |
| 输入顺序、Prompt 呈现顺序 | 固定 | 隔离相同请求的运行间变化 |
| 模型与服务 | 复用已批准的固定配置 | 避免为追求阳性结果不断更换模型 |
| 模型训练 | 不开展 | 初期研究变量位于系统执行层 |
| 额外预算 | 以无复核执行调用数为基准，优先比较 +20% 与 +40% | 分别观察受限预算与稍宽预算下的效果 |
| 性质保证 | 实现级重放与增量正确性；有限条件下的结构性质 | 通用随机稳定性证书另行研究 |

非传递比较可以作为输入存在。系统不因观测图没有环就假定关系传递；也不将不同物理算子的输出自动视为逻辑等价。

### 4.2 三类变化分开测量

1. **重复调用变化**：同一请求再次执行，结果不同。首阶段主问题。
2. **呈现扰动**：交换 A/B、改变文档顺序或 Prompt。属于鲁棒性扩展。
3. **计划变化**：更换物理算子、pivot 或分块方式。属于计划语义与物理设计扩展。

首阶段不能用第二、三类变化补充第一类变化不足的结果。扩展实验必须单独标记。

### 4.3 三个评价目标分开报告

- **重复执行一致性**：两个独立执行的最终集合是否相同。
- **任务质量**：相对于独立标签的 Recall@K，或完整有序输出上的 nDCG@K。
- **成本**：实际调用、物理尝试、token、延迟和增量重算开销。

多数票参考只用于描述与某种聚合判断的一致程度，不充当独立任务真值。缓存可满足原样重放需求；本课题评估新的独立执行，不把跨执行复用旧答案制造出的稳定性当作方法收益。

## 5. 最小形式化模型

设候选集合为 R，查询为 q，返回数量为 K，固定算子为 A。一次比较请求 x 包含查询、两篇文档的内容及顺序、Prompt 版本、模型与推理配置。相同 x 可以产生不同响应。

一次执行记录：

\[
T=\langle(x_t,z_t,s_t)\rangle_{t=1}^{L},\qquad Y=A(T),\quad |Y|=K.
\]

其中 z_t 为规范化比较结果，s_t 为恢复执行所需的状态或事件。请求身份和调用实例分开记录：同一请求的三次复核是三个物理调用实例。

策略 π 接收当前可见历史 H 和剩余预算 B，输出复核动作；根据新观测更新比较决策，再通过修复器恢复执行。完整算法记为 A_π。

主要分歧指标：

\[
D_{\mathrm{EM}}(q)=\Pr(Y^{(a)}\ne Y^{(b)}),
\]

其中 a、b 是完整算法的独立执行。另报告集合距离：

\[
D_J(q)=\mathbb{E}\!\left[1-\frac{|Y^{(a)}\cap Y^{(b)}|}{|Y^{(a)}\cup Y^{(b)}|}\right].
\]

目标为在额外预算约束和任务质量容忍范围内降低 D_EM 与 D_J。首阶段不声称求得全局最优策略。

复核优先级可用下式组织设计：

\[
\text{priority}(e)\approx
\frac{\text{复核所带来的预期结果损失减少}}
{\text{复核调用成本}+\text{预期修复成本}}.
\]

这是研究指导式；分子、分母的在线估计方法与有效性均待验证。复核导致结果改变，不自动意味着质量改善。

## 6. 关键技术边界

### 6.1 事后关键性、在线可识别性和严格免疫性

三者必须分别定义。

考虑原始执行 A>B、C>D、A>C，冠军为 A。翻转 C>D 后需要比较 A 与 D。若 A>D，答案不变；若 D>A，答案改变。这两种比较关系拥有相同的原始轨迹。

因此：

- 完整比较表可以用来计算特定表上的事后反事实影响。
- 在线分析器必须将信息不足的情况标为 unresolved，或给出保守的可能影响集合。
- 未经证明，不能将小规模完整表上测得的稀疏性称为零调用在线可识别性。

### 6.2 非传递偏好下的剪枝

A>B 和 B>C 即便分别很稳定，也不能单独推出 A>C。剪枝依据必须来自直接观测、已证明的状态不变量、明确假设，或单独评价误差的近似规则。

符号执行两个分支后能够合并是有价值的充分条件；其检测复杂度和覆盖率需要实现与测量，不能预设所有分支都能低成本处理。

### 6.3 多数票与认证

三次调用多数票是决策规则，不产生确定无误的边。单边扰动无害也不蕴含联合扰动无害。

若后续引入证书，至少明确：固定计划、允许扰动的对象、最大扰动数量、未观测比较的处理、假设与保证类型。有限扰动下的确定性性质和未来重采样的概率保证需要分别证明。

### 6.4 增量执行正确性

给定相同的已更新比较决策和相同的后续响应，增量执行应与从头执行的输出一致。这个实现性质可以先通过穷举小例子与随机对照验证。

增量执行可以节省 CPU 重算或借助缓存减少调用，但“从头重放并复用全部合法比较结果”是必要强基线。只有相对于该基线仍有收益，才能把收益归因于增量机制。

## 7. 核心假设与拟形成的贡献

| 编号 | 假设 | 验证办法 | 不成立时的含义 |
| --- | --- | --- | --- |
| H0 | 固定配置下的比较变化会导致有实际幅度的集合分歧 | 对现有固定查询完整重跑，记录基准分歧 | 当前配置缺少主要优化空间；保留为低敏感区间 |
| H1 | 执行状态包含超越单次置信度的复核价值信息 | 在线信息约束下比较策略，并做结构消融 | 停止复杂关键度分析，或保留简单拓扑规则 |
| H2 | 额外预算可以转化为端到端一致性收益，且任务质量不明显下降 | 独立重跑完整算法，比较成本—分歧—质量 | 重新检查目标与决策规则；不得只挑有利指标 |
| H3 | 局部依赖可以节省恢复工作的实际成本 | 与从头重放、合法缓存复用的基线比较 | 停止通用修复器投入；预算分配价值独立评价 |
| H4 | 不同物理算子存在可预测的优势区间 | 后续在 N、K、batch 与噪声条件下比较 | 若单一算子占优，采用固定策略，暂缓优化器 |

潜在贡献分成三层，按证据决定保留范围：

1. **机制层**：局部比较扰动通过控制流传播的可重复测量方法及适用边界。
2. **执行层**：在线可用的复核策略与增量执行机制。
3. **物理设计层**：在质量、可靠性、调用和延迟之间进行选择的模型。

仅有现象测量不足以构成完整系统贡献；若简单方法已经足够，应如实缩减设计。

## 8. 最小系统结构与工程约束

| 模块 | 输入与输出 | 首阶段要求 |
| --- | --- | --- |
| Request/Response Ledger | 请求身份、调用实例 → 原始响应与费用 | 区分逻辑比较、显式复核、HTTP 重试；保留失败 |
| Trace Executor | 固定算子、比较接口 → 轨迹与候选集合 | 固定 seed 与顺序；记录事件，不默认每步复制完整数组 |
| Probe Policy | 当前可见历史、预算 → 下一条复核比较 | 无权读取沙盒中尚未付费访问的结果 |
| Incremental Repair | 更新决策、旧轨迹 → 新状态与结果 | 新比较按需请求；超预算时保持最后完成的有效结果并标记未完成 |
| Evaluator | 隔离的轨迹、标签 → 指标和区间 | 可访问完整沙盒；该权限与在线策略分离 |

完整响应保留在原始日志中；对外报告不包含密钥。先理解现有代码和未提交修改，再在独立实验目录实现。当前 Gate 2 的冻结配置和历史目录不被本课题覆盖。

## 9. 实验原则与推进门槛

### 9.1 必要基线

无复核执行、随机复核、低置信度复核（接口可用时）、简单拓扑复核、结构与置信度结合策略、遇到的比较均三次投票的参考方法。后者实际调用数依赖执行路径，不能固定写成原运行的三倍。

另设完整表事后关键性上界，明确标记其使用了在线不可见信息。它只回答潜在收益空间，不进入公平可部署方法排名。

### 9.2 主指标与诊断指标

主指标为独立完整执行的 D_EM、D_J，独立标签质量，实际调用与端到端延迟。诊断指标包括已观测轨迹上的条件反事实关键边比例、新增比较数、复核命中率、状态复用率及尾部成本。

CER 的分母、是否按调用实例或唯一请求计数、未知边的处理均需声明。CER 不独立充当 Go/No-Go 门槛。

### 9.3 两周研究决策

优先检查预算 +40% 下的主比较，+20% 作为预算敏感性分析。小规模查询下预算需按整数调用落实，实际完成的复核数量单独报告。

进入下一阶段的建议证据为：冻结后的查询留出集上，所选策略相对预先确定的最强简单基线，D_EM 平均绝对下降至少 0.05，且相对下降至少 25%；质量点估计平均下降不超过 0.02；收益跨多个查询出现。全部阈值属于项目投入门槛，需在查看留出集前冻结，不能被表述为理论常数。

若样本区间仍宽，则标记“探索性推进”，下一阶段优先补样本。满足点估计门槛不等同于质量非劣性或广泛泛化已经证明。

增量机制单独评价：相对合法缓存重放，在预先指定的主要成本指标上减少至少 25%，并且结果一致。若只降低 CPU 成本、LLM 调用相同，需要如实报告。

完整操作协议与各类失败处理见配套两周计划。

## 10. 难度、资源与方向契合度

### 10.1 难度判断

单算子的日志、重放与局部修复原型属于中等偏高工程难度；在线复核价值估计是主要研究不确定性。通用分支分析、多翻转证书和自动计划选择显著提高难度。

在已有 runner 可复用、主要投入且接口可用的情况下，两周适合完成机制试验；单算子可用原型通常还需要后续数周。完整论文级验证可能需要数月，取决于先导结果。以上为排期估计，不构成产出承诺。

初期不需要训练大模型。主要资源为 CPU、模型调用额度、稳定的服务窗口和研究时间。所有新付费运行先给出配置、预计调用、物理尝试和金额上限；本总纲不授权付费调用。

### 10.2 与研究主线的关系

本课题直接连接语义算子、查询执行、运行间可靠性、预算控制与增量计算，符合 Database Systems、Data Infrastructure 和 Systems for AI 的交叉方向。

它可为 Agent 中昂贵外部调用的选择性复核提供启发，但现阶段不把 Agent 整体可靠性列为实证范围。GPU runtime、分布式训练和底层存储也不属于当前主贡献。

系统研究的落点应持续保留：真实执行引擎、在线信息约束、物理成本和可复现的收益。

## 11. 后续处理矩阵

| 观察结果 | 研究解释 | 后续处理 |
| --- | --- | --- |
| 复核策略有效，增量执行也有效 | 具有完整执行机制潜力 | 扩展 N/K、独立查询和第二模型，评估真实引擎集成 |
| 复核有效，增量收益小 | 预算分配是主要贡献 | 简化恢复实现，集中解释决策收益 |

| 事后上界有效，在线策略无效 | 潜在关键性难以观测 | 限时检查可观测信号；无改善则停止该选择路线 |
| 一致性改善但任务质量下降 | 更稳定的偏差被固化 | 不进入全面实现；检查目标、投票规则和标签解释 |
| 当前任务几乎没有集合分歧 | 主要优化空间有限 | 报告适用边界；扩展任务须有独立理由，避免追逐阳性结果 |

| 严格认证仅在限制条件下可行 | 保证范围有限 | 提供条件性保证，明确 unknown；不扩大证书措辞 |
